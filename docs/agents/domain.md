# Domain Docs

This is a single-context repository: `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

Before exploring or changing code:

1. Read `GLOSSARY.md` and use its terms in issues, ADRs, tests, and identifiers.
2. Read the ADRs relevant to the area.
3. If either is missing, continue without proposing upfront scaffolding; create entries only when a term or decision is resolved.

If a proposal conflicts with an accepted ADR, identify that ADR and explain why it should be reopened.
